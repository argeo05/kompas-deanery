## 2026-11-08 · D-001 · Стек и инструменты каркаса

**Решение.** Стек по SPEC §10.2:

| Слой              | Выбор                                                                                                        | Версия                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------- |
| Фреймворк         | Next.js App Router, TypeScript strict, `src/`                                                                | Next 16.4.5, React 19.3, TS 5.9 |
| Пакетный менеджер | pnpm                                                                                                         | 12.18                           |
| UI                | Tailwind CSS 4 + shadcn/ui (стиль `radix-nova`, Radix UI) + Lucide                                           | shadcn 4.23                     |
| БД / ORM          | PostgreSQL 16 (docker-compose) + Drizzle ORM (драйвер `postgres`), миграции drizzle-kit                      | drizzle-orm 0.45, kit 0.31      |
| Валидация         | Zod                                                                                                          | 4.6                             |
| Тесты             | Vitest (проекты unit / integration / security), Playwright (mobile-360, desktop-1440) + @axe-core/playwright | Vitest 5.1, Playwright 1.65     |
| Качество          | ESLint 9 (next + prettier), Prettier, `tsc --noEmit`, gitleaks (pre-commit и CI)                             | gitleaks 8.30                   |
| Контейнер         | Docker multi-stage, `output: "standalone"`, node:24-alpine                                                   | —                               |

**Почему.**

- Next.js: SSR для быстрого LCP на телефоне, API и UI в одном проекте, модели хорошо знают фреймворк (SPEC §10.1).
- Drizzle, а не Prisma: ближе к SQL, удобнее для RLS и `SET LOCAL app.user_id` в `withUserTx` (SPEC §10.2, DEEPSEEK-TASKS §2).
- Radix, а не Base UI: `shadcn init -d` теперь по умолчанию ставит `base-nova` (Base UI), а SPEC §10.2 называет Radix. Переинициализировали с `-b radix -p nova`.
- Три Vitest-проекта, чтобы Stop-хук гонял только быстрые unit и security, а интеграционные с БД шли в `verify:ds`.
- Playwright гоняет production-сборку (standalone): e2e проверяют то же, что попадёт в Docker.

**Мелкие решения каркаса.**

- `agentRules: false` в next.config: Next 16 иначе пишет свой блок в AGENTS.md, а там лежат правила DeepSeek.
- pnpm 12 блокирует build-скрипты пакетов. Разрешён только `esbuild` (`pnpm-workspace.yaml → allowBuilds`).
- `"type": "module"` в package.json: ESM-конфиги без предупреждений, top-level await в `db/*.ts`.
- Пункт §12.3 «PreToolUse на `git commit` → gitleaks» закрыт git-хуком `.githooks/pre-commit`. Он ловит любой коммит, от Claude, DeepSeek и человека, поэтому отдельный хук Claude не нужен.
- PostToolUse-хук запускает Prettier и ESLint по файлу (§12.3). В C.5 указан только Prettier, ESLint добавлен по таблице §12.3.

**Последствия.** Node ≥ 24. Для e2e нужен `pnpm exec playwright install chromium`, для интеграционных тестов — `pnpm db:up`.

## 2026-11-08 · D-002 · Схема БД, RLS, Better Auth и обвязка API (сессия A2) — закрыт в D-005 (C1)

**Решение.**

- **Схема.** Все таблицы SPEC §10.4 в `db/schema/*` (auth, people, study, requests, communication, system). Добавлены таблицы, без которых контракты DS-тикетов не реализовать: `units` (подразделения), `class_notes`, `schedule_change_views`, `ics_tokens`, `rate_limits`, `accounts`/`verifications` (Better Auth).
- **studentId = userId.** `student_profiles.user_id` — первичный ключ и он же `student_id` во всех личных таблицах. В guards `studentId === userId`, политики RLS сравнивают с одним значением.
- **Better Auth ↔ SPEC.** Таблица `users` с колонкой `login` (свойство `username` для адаптера). Хеш пароля — в `accounts.password_hash`, так устроен Better Auth. Id — UUID (`generateId: "uuid"`). Вход — `POST /api/auth/sign-in/username`, а не `/api/auth/login` из §9.7.
- **RLS.** Отдельная миграция `0001_rls.sql`. Приложение подключается владельцем БД, а `withUserTx` делает `SET LOCAL ROLE kompas_app` и `set_config('app.user_id')`. Владелец RLS обходит (миграции, сид, Better Auth), роль приложения — нет. Сотрудник видит студентов своего факультета; подразделение без факультета (студенческий офис) видит все. Оценки сотруднику закрыты. `request_events`, `grade_history`, `audit_log`, `events` только дописываются (UPDATE и DELETE отозваны). Справочники доступны роли только на чтение, из `users` — только безопасные колонки.
- **Код проверки документа** = HMAC(секрет, id документа). В БД лежит только SHA-256, а ссылку `/verify/...` можно показать повторно.
- **`requests.delivery` nullable.** У заявлений (`app_*`, `data_fix`) способа получения нет.
- **Proxy `/staff/*`** сам отвечает 403 и HTML «Раздел для сотрудников». `NextResponse.rewrite(url, { status: 403 })` в рантайме Next отдаёт 200 (проверено на standalone-сборке). В процессе тестов он давал 403, то есть тест был ложно зелёным.
- **Тестовый маршрутизатор.** `apiAs()` вызывает экспорты `route.ts` напрямую, с настоящей cookie Better Auth. Для отсутствующего маршрута он бросает исключение, а не возвращает 404, иначе тест изоляции прошёл бы на несуществующем эндпоинте. `idor.spec.ts` проверяет, что каждый `route.ts` есть в манифесте.

**Отклонения от SPEC (осознанные, к пересмотру).**

| SPEC                                                           | Сейчас                                                             | Почему / что дальше                                                                                                      |
| -------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| §9.2: в БД SHA-256 от id сессии                                | Better Auth хранит случайный токен как есть; cookie подписана HMAC | Хешировать токены Better Auth 1.7 не умеет. Утечка БД = угон сессий; принимаем для демо, IP храним HMAC-ом               |

| §6.1 п.3, §9.7: 5 неудачных на логин+IP за 15 мин → пауза 30 с | Rate limit Better Auth в БД: 5 попыток входа за 30 с на IP         | Встроенный лимит ключуется по IP+путь и считает все попытки. Счётчик неудач по логину+IP — TODO сессии экрана входа (A3) |
| Context7 через MCP                                             | Публичный эндпоинт context7.com + исходники пакета                 | Context7 MCP в `.mcp.json` не подключён                                                                                  |

**Последствия.** В `.env` нужны `BETTER_AUTH_SECRET` и `BETTER_AUTH_URL`, без секрета production не стартует. В CI у job `checks` появилась PostgreSQL. Новая личная таблица требует политики новой миграцией и строки в `tests/security/rls.spec.ts`. `withIdempotency` не атомарен с созданием сущности: при падении процесса между ними ключ «зависает» до ежедневного сброса.

**Аудит A2 (субагент security-auditor), исправлено:** закрыты `/sign-in/email`, `/is-username-available`, `/update-user`, `/change-email`, сброс пароля по почте (`disabledPaths`); `immutableUsername`; before-хук запрещает демо-аккаунтам `/change-password`; битый курсор (36 дефисов) давал 500 — теперь 422.

**Аудит A2, открыто (не влияет на текущие эндпоинты):**

- Rate limit верит заголовку `AUTH_IP_HEADER`. Без прокси, который его перезаписывает, клиент подставляет любой IP, а без заголовка все попадают в общий bucket. Решить в сессии деплоя (C-25): прокси перед контейнером + fail-fast, если заголовок не настроен.

## 2026-11-08 · D-003 · TDD-контракт DS-01…07, календарь, шкала, демо-сценарии (сессия A3)

**Решение.**

- **Заглушки вместо отсутствующих модулей.** `src/lib/{workdays,digest,grading,semester-status,windows,request-fsm,today}.ts` содержат зафиксированные сигнатуры, тела вызывают `notImplemented("DS-0X")`. Без них `tsc` падал бы на импорте, и `pnpm verify:ds` не доходил бы до тестов. Каждый тест падает с ошибкой «DS-0X: не реализовано». Против эталонной реализации (она лежала в scratchpad и в репозиторий не попала) все 265 тестов зелёные.
- **DS-01.** Подача после 17:00:00 МСК, в выходной или праздник переносится на следующий рабочий день E. Срок — 18:00 N-го рабочего дня после E, сам E не считается. `workdaysBetween(a, b)` считает рабочие дни d с день(a) < d ≤ день(b), при b < a результат отрицательный. Сокращённые предпраздничные дни остаются рабочими.
- **DS-02.** Слот сравнивается с точностью до секунд (13:00:30 → 19:00). Тихие часы — полуинтервал [from, to): 07:00 уже не тихое время. Слот, попавший в тихие часы, пропускается. Срочное и `immediateCategories` приходят в момент окончания тихих часов.
- **DS-03.** `maxPossible` — сколько ещё можно набрать (Σ wⱼ·100 по несданным), а не максимальный итог. Так в примере SPEC: «18 баллов из 30 доступных». `needed` показывается и тогда, когда цель недостижима.
- **DS-04.** Риск — строго больше 70 % оставшегося. Нет несданного и порог не набран — тоже NEED_OVER_70. `admitted: null` причиной не считается.
- **DS-05.** Выходные не исключаются. Окно ровно minMinutes подходит.
- **DS-06.** Недопустимый переход бросает `InvalidTransitionError` (экспорт `src/lib/request-fsm.ts`), обработчик переводит его в 409.
- **DS-07, пробел в SPEC §6.2.** Пять веток не покрывают случай «сегодня пара будет, но позже чем через 3 ч», например у Максима в 12:00 при паре в 19:00. Такой случай возвращает `day_off` с `nextClassAt` = начало этой пары. Контракт `Hero` не меняется, текст для UI — «Пар пока нет. Ближайшая — сегодня в 19:00». Пары с изменением `cancelled` не бывают «сейчас» и «скоро». Если отменены все пары дня, это `day_off`. **К подтверждению человеком.**
- **Календарь.** `config/holidays.ts` заполнен по постановлениям № 1466 (2026) и № 1187 (2027) и сверен с КонсультантПлюс. Самопроверка: 247 рабочих дней в каждом году, как в официальном календаре. 20.02.2027 — рабочая суббота.
- **Шкала.** В `config/grading.ts` полосы A–F, пороги оценок 85/70/55 взяты из SPEC. Все значения помечены условными. Тесты шкалы читают конфиг, поэтому смена порогов их не ломает.
- **Демо-сценарии.** `db/seed/demo-accounts.ts` сам создаёт расписание ±2 недели, оценки, сессию, дедлайны, уведомления и настройки для групп Б-ЭК-101 и М-ЦМ-11, а также очередь Елены: 4 студента очереди и их заявки. Популяция DS-40 их не трогает (уточнено в DEEPSEEK-TASKS DS-40). Сроки демо-заявок заданы явно, чтобы сценарий не зависел от DS-01.
- **Шаблоны уведомлений.** `src/server/notify-templates.ts` принадлежит Claude: это тексты для людей, сервисы DeepSeek только вызывают `renderNotification`. Тексты черновые, финальная редактура — ux-copy-editor в фазе C.
- **`ical.js` (MPL-2.0)** — только devDependency для разбора ICS в тестах DS-22. Это исключение того же рода, что `@axe-core/playwright`.

**Последствия.** Когда тикет DS-0X готов, Claude при ревью удаляет из `src/lib/not-implemented.ts` последний вызов, а затем и сам файл. Новый алиас `@config/*` прописан в tsconfig.

**Дополнение D-003 (решение человека).** Stop-хук в `.claude/settings.json` запускает юнит-тесты с `--exclude` для семи файлов DS-01…07: TDD-тесты красные, пока их не реализует DeepSeek. Когда тикет смёрджен, Claude убирает его файл из исключения. `pnpm verify:ds` и CI проверяют все тесты без исключений.

## 2026-11-08 · D-005 · Безопасность: хвосты D-002 закрыты (этап C1)

**Решение.**

- **Токен сессии.** Better Auth 1.7 хешировать токен не умеет, поэтому адаптер БД обёрнут (`src/server/auth/session-token-hash.ts`): в `sessions.token` лежит SHA-256, а Better Auth и cookie видят исходный токен. Токен случайный (32 символа), соль не нужна. Из-за обёртки отключены `/list-sessions` и `/revoke-*` (они вернули бы хеши и не отзывали бы сессии); «выйти везде» делается удалением строк по userId. **При выкатке очистить `sessions`**: старые токены лежат открыто.
- **Cookie.** В production имя `__Host-kompas.session_token` (Secure, Path=/, без Domain); встроенный `__Secure-` отключён. В разработке без префикса.
- **Лимит входа.** По IP: 5 попыток за 30 с (Better Auth, БД). По логину: 20 неудачных за час (в памяти процесса, `rate-limiter-flexible`); попытка резервируется до проверки пароля (нет гонки), успешный вход её возвращает. Осознанный риск: чужой может заблокировать демо-логин на час, 20 неудач; принят ради простоты, ключ «логин+IP» из SPEC §6.1 не взят, потому что его обходят сменой IP. Если станет проблемой на показе, исключить isDemo из этого лимита.
- **Доверенный IP.** Только заголовок `AUTH_IP_HEADER` (по умолчанию `x-real-ip`), который перезаписывает Caddy (`header_up X-Real-IP {remote_host}`). `X-Forwarded-For` не читается нигде. В production без `TRUSTED_PROXY=true` приложение не обслуживает вход и `/api/verify` (fail-fast). Это снимает открытый вопрос D-002 про `/api/verify`. Для C10: в окружение контейнера добавить `TRUSTED_PROXY=true`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, и `.env.example` (я его не мог править).
- **Заголовки (§9.6).** CSP с nonce ставит `src/proxy.ts` на каждую страницу: `script-src 'self' 'nonce-…' 'strict-dynamic'`, без `unsafe-inline` и `unsafe-eval`; `style-src 'self' 'nonce-…'` и отдельно `style-src-attr 'unsafe-inline'` (атрибуты `style=""` от React и компонентов; кода через них не выполнить). Остальные (HSTS, nosniff, Referrer-Policy, Permissions-Policy, COOP, X-Frame-Options) заданы в `next.config.ts` и повторены в ответах proxy. `upgrade-insecure-requests` не включён (ломает http://localhost в e2e), его роль играет HSTS.
- **Динамический рендеринг.** Nonce подставляется только при рендеринге на запрос, статический HTML остался бы без него и CSP заблокировала бы гидратацию. Поэтому в корневом layout `await connection()`, а `cacheComponents` и `partialPrefetching` убраны из `next.config.ts` (в коде не использовались). Цена: страницы не предрендерены; для PWA (C7) офлайн строится на service worker, а не на PPR.
- **proxy `/staff`.** Путь нормализуется (регистр, `%`-коды, двойные слэши), matcher `/staff/:path*` работает и на prefetch. Редирект на `/login` строится от `BETTER_AUTH_URL`.
- **Манифест.** `pending` убран, пропусков в security нет (232 теста, 0 skipped): проверки списков регистрируются только для маршрутов с `ownerIds`. Ещё не созданные маршруты SPEC (`POST /api/assistant`, `POST /api/jury/reset`) лежат в `tests/security/not-implemented.ts` и обязаны отвечать 404 (e2e).

**Аудит C1 (security-auditor), исправлено:** отключены маршруты сессий и админ-маршруты; резервирование попытки входа; нормализация пути в proxy; редирект не от `req.url`; fail-fast TRUSTED_PROXY и для `/api/verify`; matcher без `api`-префикса-ловушки; HMAC IP без пустого секрета.

## 2026-11-09 · D-011 · Заявки, справки, PDF с QR и /verify (этап C4)

**Решение.**

- **Когда выдаётся документ.** Электронный документ создаётся при переходе `ready` (а не `issued`): по SPEC §6.5 на «Готова» студент уже скачивает PDF. `issue` только закрывает заявку. Бумажный оригинал документа не создаёт, студент видит «Где забрать». Повторная выдача идемпотентна.
- **PDF строится при скачивании** из данных заявки и профиля (`GET /api/me/documents/:id/file`), а не хранится как файл. Файл нельзя подменить, код проверки не хранится (D-005, `verify-code.ts`). Цена: PDF пересобирается при каждом скачивании (лимит 20 в минуту на студента). Шрифт Onest 400/600 склеен из latin и cyrillic в один TTF (react-pdf не умеет вариативные и составные шрифты), лежит в `src/server/pdf/fonts` с лицензией OFL и включён в standalone через `outputFileTracingIncludes`.
- **Адрес в QR** берётся из `BETTER_AUTH_URL` (в production обязателен, иначе по `Host` студент мог бы получить QR на чужой домен); вне production — из запроса.
- **Новый эндпоинт** `POST /api/me/requests/:id/seen` (204): гасит точку «Новое» в списке. Отдельный запрос, а не побочный эффект GET, чтобы предзагрузка страницы не «читала» события. Существующий контракт не менялся.
- **/verify/<код>** — серверная страница без входа с тем же лимитом 30/мин на IP, что и API (`src/server/verify-limit.ts`). Показывает тип, дату выдачи и «действителен / отозван / не найден»; явный блок «Что мы подтверждаем / Чего не показываем». `noindex`.
- **Форма** строится из `formSchema` типа (схема Zod на клиенте, обязательность проверяется на клиенте; сервер при создании её не требует, доработка идёт через `needs_info`). Черновик в `localStorage` с id студента в ключе, в try/catch. `Idempotency-Key` создаётся один раз на попытку и сохраняется до успеха, поэтому повтор не создаёт дубль. «Подать заново» открывает форму с полями исходной заявки; способ получения и число экземпляров остаются прежними (так устроен `resubmit`).
- **Трекер**: только события из `request_events`, новое событие появляется один раз (`animate-ink-in`), впереди серым показаны ещё не наступившие этапы; для чтения с экрана они помечены «Ещё впереди».
- **Зависимости**: `@react-pdf/renderer`, `qrcode` (+ `@types/qrcode`), в тестах `pdfjs-dist` (Apache-2.0) для проверки текста и QR внутри PDF.

**Развёртывание.** В production обязательны `VERIFY_SECRET` и `BETTER_AUTH_URL`. Без `VERIFY_SECRET` переход `ready` для электронной справки отвечает 500 (найдено в e2e). Смена `VERIFY_SECRET` ломает все выданные QR. Для e2e секрет задан в `playwright.config.ts`. `.env.example` не обновлён (нет доступа).

**Отклонено из аудитов.** Хранение лимитов в Postgres (концепт, один процесс); пометка «указано заявителем» в PDF (водяной знак и подпись-заглушка уже исключают принятие за настоящий документ); вкладки «Активные/Архив» без объявления смены (скелетон озвучивается).

- **Поиск на сервере** (`GET /api/me/search`, `services/search.ts`): типы заявок (заголовок и синонимы из БД), пары и дисциплины студента, преподаватели и аудитории из его пар на 3 недели вперёд, объявления через ту же видимость, что у ленты, статьи справочника (`tsvector` + заголовок + теги). Опечатки: `pg_trgm` (`word_similarity`, миграция 0003). Разговорные слова: словарь `src/lib/search-synonyms.ts`. Порог схожести 0,4: «макроэкномика» находит дисциплину, мусорный запрос даёт пустую выдачу.
- **Справочник попал в БД.** `kb_articles` не заполнялась в фазе B; сид `db/seed/kb.ts` читает 25 файлов `content/kb/*.md` (идемпотентный upsert), для уже засеянной базы — `pnpm db:seed-kb`. Страницы `/help` и `/help/[slug]`, API `/api/me/kb`. Это дополнение к карте URL §5.4.
- **Markdown объявлений без HTML.** `src/lib/markdown.tsx` разбирает абзацы, заголовки, списки, `**жирный**`, `*курсив*`, `[ссылки](…)` в узлы React; сырой HTML остаётся текстом, ссылки — белый список (http, https, mailto, относительные). Санитайзер-библиотека (DOMPurify) не нужна, `dangerouslySetInnerHTML` не используется. Тест с 11 XSS-векторами (AC-6.4).
- **ICS по RFC 5545 своим сборщиком** (`src/lib/ics.ts`): VTIMEZONE Europe/Moscow, время с `TZID`, свёртка строк по 75 октетов, экранирование, `SEQUENCE` растёт с числом переносов, UID `class-<id>@kompas` и `deadline-<id>@kompas` стабильны. Причина: библиотека `ics` пишет только UTC или «плавающее» время. Зависимость `ics` в `package.json` осталась, но больше не используется (убрать при чистке зависимостей). Отдельный календарь дедлайнов: `?cal=deadlines`, только пары — `?cal=schedule`. Токен отзывается кнопкой «Сбросить ссылку» (старый — 404).
- **Уведомления.** Вкладки в адресе (`?tab=`), якорь `#a-<id>` для объявления, карта цели `src/lib/notification-link.ts` (каждый вид цели — существующая страница). Настройки: три режима на категорию, пресеты окон, «Только срочное» вместо «Выключить всё». Сервер всегда отдаёт `preset: "default"`, поэтому интерфейс определяет пресет по слотам.
- **Дедлайны.** `/study/deadlines` — третья вкладка «Учёбы». Кнопка «Когда займусь?» только для дедлайнов со звёздочкой или с риском (SPEC §6.7 п.8). План — окно без пар (до 90 минут), место, первое действие; формулировка «Если …, то …» показывается в карточке дословно.
- **Обращения.** `/support`, `/support/new`, `/support/[id]`. Кнопка «Написать через Компас» в листе пары и карточке дисциплины открывает форму с темой и ссылкой на объект (сервер проверяет владельца).
- **Норматив ответа.** Показываем «Обычно отвечаем в течение рабочего дня». Счётчик «в среднем 4 ч» из SPEC §6.8.1 п.6 не выводим: в демо-данных нет ответов, на которых его можно честно посчитать.
