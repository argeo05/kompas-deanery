# DS-11 — открытые вопросы и принятые допущения

Тикет выполнен; ниже место, где контракт (или ТЗ) не определял поведение, и какое допущение принято. Ревью Claude может заменить допущение без переделки структуры кода.

## 1. Что такое `weekNumber` в `ScheduleDTO`?

**Неясно.** SPEC §6.3 п.4 упоминает «Неделя 11 · числитель» (конфигурируемо), но ни контракт, ни конфиги (`config/`) не определяют точку отсчёта семестра. Поля «дата начала семестра» в схеме БД нет.

**Принято:** `weekNumber` — номер ISO-недели даты `from` (неделя с понедельника; `2026-11-12` → 46), `weekParity` (`odd`/`even`) — чётность этого номера. Детерминировано, без новых конфигов.

**Альтернатива (лучше, если UI захочет «Неделя 11» референсного примера):** номер недели семестра от настроенной даты начала семестра — тогда нужен `config/semesters.ts` или аналогичное решение Claude.

## 2. Переносы через границу запрошенного диапазона

Пары фильтруются по **исходному** `startsAt` (репозиторий `listMyClasses` заморожен, координатор запретил его правки):

- пара, перенесённая **из** других дней внутрь диапазона, в выдачу не попадёт (её новый слот в диапазоне, но исходное время вне);
- призрак пары, перенесённой **из** диапазона на другой день, показан (его исходный слот внутри), но его новое время может лежать вне диапазона.

Для дефолтной недели и демо-данных (перенос внутри одного дня) эффекта нет. Если нужно честно — добавить в репозиторий выборку по `OR (startsAt в диапазоне, EXISTS change с new_starts_at в диапазоне)`. Предлагаю сделать при ревью.

## 3. Несколько изменений на одну пару

Контракт допускает ровно один `change` на пару (`ClassDTO.change: ScheduleChangeDTO | null`). Принято: берётся **последнее** по `createdAt` (и `id`) изменение. Очередность «cancelled → then added» и т. п. не моделируется.

## 4. `markChangesSeen` молча отбрасывает чужие id (уже в замороженном репозитории)

`POST seen` с id чужого изменения возвращает 204 без эффекта. Альтернатива — 404 — не выбрана, потому что это пометочный bulk-запрос («отметить всё увиденным»), а не обращение к ресурсу.
