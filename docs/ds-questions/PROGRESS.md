## Решения, о которых стоит помнить Claude (ревью фазы C)

- Обязательность `formSchema.required` **не** проверяется при создании заявки — манифест
  изоляции ожидает `fields: {}` → 2xx; доработка через needs_info (сервис отдаёт 422 только
  на неизвестные/невалидные по типу поля). Документировано в `docs/ds-questions/` и в коде.
- Дефолт `limit` staff-очереди — 50 (максимум Paged), не 20: манифест создаёт десятки
  фикстурных заявок с равным сроком; page1 мирит это через `date_trunc('second', due_at)`
  - сортировку `number DESC`.
- События/сообщения: детерминированный порядок при замороженных часах — `date_trunc`+`ctid`
  (ctid не монотонен на live-данных, поэтому список очереди — trunc+number).
- verify-код: `docPublicCode = sha256(VERIFY_SECRET:docId)`, в БД только sha256(publicCode).
- `request_ready` → уведомление класс `urgent` передаётся явно в `notify()` (шаблон не умеет).
- `schedule_teacher_changed` остаётся `personal` (повышение класса запрещено без Claude).
- Уведомления о будущих `publishAt` уходят сразу (упрощение v1.1).
- ICS-токен: 256 бит base64url; в БД sha256; сырой токен в кэше `idempotency_keys` (решение
  нуждается во втором взгляде Claude — см. `docs/ds-questions/DS-22.md`).
