Предпроверка (быстрый расчёт WCAG 2.x): --warn #B26A00 = 3,89 / 4,24 / 3,56 на bg / surface / surface-2; --ok #1E7F5C = 4,54 / 4,95 / **4,16**; --alert #C2413A = 4,69 / 5,11 / **4,30**; --accent = 5,06 / 5,52 / 4,64. То есть на --surface-2 не проходят ещё --ok и --alert. Тёмная тема проходит с запасом.

1. **Скрипт** `scripts/check-contrast.ts`: без зависимостей, запуск `node scripts/check-contrast.ts` (Node 25 исполняет TS сам; tsx и pnpm install не нужны). Токены — объект в скрипте, синхронный с §7.2. Пары: текстовые токены (ink, ink-2, accent, ok, warn, alert, info, coral) × bg / surface / surface-2 ≥ 4,5; accent-ink на accent; -fg на -bg бейджей ≥ 4,5; focus, line-как-граница элемента, course-0…9 на surface ≥ 3. Печатает таблицу, exit 1 при провале.
2. **Подбор значений** — меняем только светлоту в HSL/OKLCH, оттенок держим: --warn ≈ #9A5B00, --ok и --alert темнее до ≥ 4,5 на surface-2. В §7.2 колонка «контраст (bg / surface / surface-2)» для обеих тем.
3. **Статусные токены**: добавляем --info (В работе) и --coral (отклонено, «Нужно действовать»). Решение: отмена пары → --coral (это не системная ошибка, принцип «Не стыдим»/спокойствие), --alert остаётся только для ошибок системы. Для ok / warn / info / coral / alert / neutral — пары `-bg`/`-fg` в обеих темах. Приводим к токенам §6.2 (красная/янтарная метка), §6.3 (янтарная точка), §6.4 (светофор), §6.5 (таблица статусов), §7.4 StatusBadge (таблица статус → токен → иконка). Итоговый grep цветов словами по всему SPEC.
4. **Цвета дисциплин** --course-0…9 (свет/тёмн), приглушённые, разведены по оттенку ~36°, ≥ 3:1 к --surface; правило «по colorIndex из API (0..9), смысла не несёт» — заменяет «по course_id».
5. **Типографика**: таблица ролей display / h1 / h2 / h3 / body / body-strong / caption / nav-label / button / numerals — размер моб./деск., line-height, вес, letter-spacing (Unbounded крупно −0,02…−0,03em). Отдельно «98 / Отлично / A»: крупно баллы (Unbounded/tabular), слово и буква — вторичные; вид в списке дисциплин и в карточке.
